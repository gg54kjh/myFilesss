Как быть, если код громоздкий?

Если ваш код большой и вы не хотите хранить его как огромную строку в textContent, есть несколько профессиональных способов решения этой задачи для разработки или личного пользования:

Способ А: Использование Blob (Если нужно обойти загрузку по сети)

Если код большой, вы можете хранить его в расширении или передавать через localStorage/GM_getValue (через Tampermonkey), а затем создавать локальный URL:

// Допустим, код лежит в переменной hugeCodeString
const blob = new Blob([hugeCodeString], {type: 'text/javascript'});
const url = URL.createObjectURL(blob);

const scr = document.createElement('script');
scr.src = url;
document.documentElement.appendChild(scr);

Этот способ часто работает, потому что blob: URL считается “локальным” для текущего документа.

Способ Б: Tampermonkey + @resource

Если вы используете Tampermonkey, у него есть мощный механизм @resource. Он скачивает файл до того, как страница загрузится (в контексте менеджера расширений, а не самой страницы), поэтому ограничения CORS и CSP к нему не применяются.

// ==UserScript==
// @name         My Script
// @match        https://yandex.ru/*
// @resource     myScriptData https://example.com/my-big-script.js
// @grant        GM_getResourceText
// ==/UserScript==

const myCode = GM_getResourceText("myScriptData");
const scr = document.createElement('script');
scr.textContent = myCode;
document.documentElement.appendChild(scr);

Это лучший вариант для вашей задачи. GM_getResourceText скачает ваш файл на сервере расширения, обойдет все блокировки Яндекса, и вы получите готовый текст, который сможете безопасно “инжектнуть” в страницу через textContent.

Резюме:

  1. Почему блокируется fetch? Потому что нет заголовка Access-Control-Allow-Origin на вашем сервере.
  2. Почему блокируется src? Потому что CSP Яндекса запрещает загрузку скриптов не из списка разрешенных доменов.
  3. Как победить? Используйте Tampermonkey с директивой @resource. Это решит обе проблемы: и загрузку громоздкого файла, и обход ограничений безопасности Яндекса.

3. Есть ли альтернатива для еще большей легкости?

Если вы боитесь, что @resource как-то перегрузит Tampermonkey, есть еще один метод — «скрипт внутри скрипта»:

Вы можете просто скопировать код вашего внешнего файла и вставить его прямо в файл вашего Tampermonkey-скрипта (например, внутри функции или переменной):

// ==UserScript==
// @name         Мой огромный скрипт
// @match        https://yandex.ru/*
// ==/UserScript==

(function() {
    const hugeCode = `
        // Здесь ваш огромный код
        // ... (десятки тысяч строк)
    `;
    
    const scr = document.createElement('script');
    scr.textContent = hugeCode;
    document.body.appendChild(scr);
})();

Плюсы этого метода:

  • Никаких внешних запросов вообще.
  • Никаких дополнительных ресурсов в менеджере.
  • Максимальная надежность (код всегда с вами).

Минусы:

  • Неудобно редактировать (редактор Tampermonkey может немного «тормозить» при очень большом объеме текста).
  • Если у вас много скриптов, каждый из них будет содержать этот текст в памяти.

Итог:

  1. @resource — это профессиональный стандарт. Это очень эффективный и «легкий» метод, так как он кэширует данные локально.
  2. Браузер не «почувствует» нагрузки. Даже если ваш скрипт будет весить 1–2 МБ, это капля в море для любого современного компьютера.
  3. Не переживайте за «тяжесть». Главный враг производительности в браузере — это не размер текста в памяти, а количество сетевых запросов и манипуляции с DOM (перерисовка страницы). @resource эти проблемы решает идеально.

Если ваш код больше 2-3 мегабайт, тогда стоит задуматься о декомпозиции, но в 99% случаев @resource — это именно то, что вам нужно.
