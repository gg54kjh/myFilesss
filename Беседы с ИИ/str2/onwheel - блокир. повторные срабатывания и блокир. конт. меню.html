Ваш способ рабочий, но использование HTML-атрибутов для хранения временного состояния — не лучшая практика. Браузер тратит лишние ресурсы на обновление DOM-дерева и перерисовку. 
Какой способ лучше?
Ваша идея со свойством объекта (el.my_property) намного лучше и производительнее. Однако, чтобы не засорять сам DOM-элемент сторонними свойствами, лучше использовать замыкание (closure). 
Замыкание позволяет хранить флаг внутри обработчика, полностью изолируя его от глобальной области видимости и самого элемента. 
Альтернативные и более корректные способы
1. Флаг через замыкание (Рекомендуемый) 
Переменная isLocked создается один раз и доступна только внутри возвращаемой функции. Это чистый JS без изменения DOM. 
javascript
const handleWheel = (() => {
  let isLocked = false;
  return function(e) {
    if (isLocked) return;
    isLocked = true;
    setTimeout(() => isLocked = false, 1200);

    // ---- Ваше действие здесь
    console.log('Сработало!');
  };
})();

el.addEventListener('wheel', handleWheel);
2. Запись свойства в объект элемента (Как вы предлагали) 
Это быстрее, чем setAttribute, так как меняется свойство объекта в памяти, а не HTML-код. 
javascript
el.addEventListener('wheel', function(e) {
  if (this.isWheelLocked) return;
  this.isWheelLocked = true;
  setTimeout(() => this.isWheelLocked = false, 1200);

  // ---- Ваше действие здесь
});
3. Использование CSS-класса 
Если во время блокировки прокрутки вам нужно визуально изменить элемент (например, уменьшить непрозрачность или заблокировать курсор), используйте класс. 
javascript
el.addEventListener('wheel', function(e) {
  if (el.classList.contains('is-locked')) return;
  el.classList.add('is-locked');
  setTimeout(() => el.classList.remove('is-locked'), 1200);

  // ---- Ваше действие здесь
});
Важное примечание по событию wheel
Для улучшения производительности скролла (особенно на мобильных устройствах или тачпадах) всегда добавляйте флаг passive: true, если внутри обработчика вы не вызываете e.preventDefault(). 
javascript
el.addEventListener('wheel', handleWheel, { passive: true });

Запрос fetch к серверу на получение исходного кода страницы.
14:23
Раз вы делаете сетевой запрос fetch, жесткий таймер в 1200 мс — ненадежное решение. Если сервер ответит медленнее (например, через 1500 мс), блокировка снимется раньше времени, и повторные прокрутки колесика отправят новые дублирующие запросы. 
Лучший подход в данном случае — блокировать отправку на время фактического выполнения запроса (пока promise находится в состоянии pending). 
Идеальное решение через Async/Await и замыкание
Используйте флаг isLoading. Он гарантирует, что пока fetch не завершится (успешно или с ошибкой), новые запросы отправляться не будут. 
javascript
const loadPageSource = (() => {
  let isLoading = false; // Флаг активного запроса

  return async function(e) {
    if (isLoading) return; // Игнорируем колесико, если запрос уже идет
    isLoading = true;

    try {
      const response = await fetch('/get-page-source');
      const data = await response.text();
      // ---- Ваше действие с исходным кодом страницы ----
      console.log(data);
    } catch (error) {
      console.error('Ошибка запроса:', error);
    } finally {
      isLoading = false; // Снимаем блокировку ВСЕГДА, даже при ошибке
    }
  };
})();

el.addEventListener('wheel', loadPageSource, { passive: true });
Почему это лучше таймера:
  • Защита от DDoS: Новые запросы физически не отправятся, сколько бы пользователь ни крутил колесико во время загрузки.
  • Динамическое время: Если сервер ответит за 100 мс, интерфейс разблокируется сразу. Если за 3 секунды — блокировка продержится все 3 секунды.
  • Надежность: Конструкция finally гарантирует, что флаг сбросится в любом случае, и код не «зависнет» навсегда при сбое сети.

Ваш способ рабочий, но удаление обработчика по таймеру (setTimeout) создает «гонку условий». Если пользователь отпустит кнопку через 600 мс, контекстное меню все равно появится, так как обработчик уже удалился. Если он отпустит её через 100 мс, то меню заблокируется, но еще 400 мс легитимные клики правой кнопкой мыши в других местах будут ломаться. 
Вместо привязки ко времени (0.5 сек) гораздо надежнее привязаться к конкретным событиям мыши. 
Как сделать правильно: Флаг при прокрутке
Идея в том, чтобы блокировать контекстное меню только в том случае, если во время удержания правой кнопки мыши происходило вращение колесика. 
javascript
let isContextMenuBlocked = false;

// 1. Фиксируем прокрутку с зажатой правой кнопкой
document.addEventListener('wheel', (e) => {
  if (e.buttons === 2) { // 2 означает, что зажата именно правая кнопка
    isContextMenuBlocked = true;
  }
}, { passive: true });

// 2. Блокируем меню, только если флаг активен
document.addEventListener('contextmenu', (e) => {
  if (isContextMenuBlocked) {
    e.preventDefault();
    isContextMenuBlocked = false; // Сразу сбрасываем флаг
  }
});
Почему этот способ лучше:
  • Стопроцентная точность: Меню заблокируется гарантированно, независимо от того, крутил пользователь колесико 100 миллисекунд или 5 секунд.
  • Никаких побочных эффектов: Стандартное контекстное меню в системе не ломается при обычных кликах правой кнопкой мыши.
  • Чистый код: Не нужно постоянно добавлять и удалять слушатели событий (addEventListener / removeEventListener) и плодить таймеры.
